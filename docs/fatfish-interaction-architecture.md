# Fatfish 动画、语音与 Agent 架构约束

状态：已确认的产品与工程约束  
最后更新：2026-11-02  
适用范围：ESP-MOSAICO Fatfish 固件、动画资源构建工具、本地 Agent 服务

本文记录 Fatfish 后续开发必须共同遵守的架构边界。它用于防止动画、ASR、Agent、聊天与升级功能分别实现后争抢内部 Flash、NAND、内存、音频设备或 UI 状态。

文中的 **必须**、**禁止**、**应该** 分别对应 MUST、MUST NOT、SHOULD。

## 1. 产品目标

Fatfish 应同时具备两层能力：

1. 设备端即时互动：按钮、触摸、传感器、基础离线动作、动画、音效和断网降级。
2. 本地部署的 Agent：ASR、提示词、多轮对话、工具调用、记忆和可选 TTS。

“本地 Agent”指部署在用户局域网中的 Mac、PC、NAS 或服务器，不指在 ESP32-S31 上运行完整 ASR 或大语言模型。

设备断开 Agent 后仍必须能启动、显示、播放待机动画并接受基础输入。Agent 不得成为设备启动和 UI 渲染的硬依赖。

## 2. 已知硬件与当前分区

- MCU：ESP32-S31。
- 屏幕：480 × 480，RGB565。
- 内部 Flash：16 MiB。
- `main_app`：8000 KiB。
- `ui_apps`：3200 KiB。
- `system`：3000 KiB。
- 板载 SPI NAND：配置容量 `0x40000000`，即 1 GiB，挂载点 `/nand`。
- 音频输入输出：板载麦克风、ES8311 与扬声器功放。

2026-11-02 的构建快照：

- 主固件约 5.74 MiB。
- 当前 UI 资源约 3197.58 KiB / 3200 KiB。
- 两个完整 10 秒待机素材已经使 UI 分区接近上限。

因此，**禁止继续把批量动画直接编入 `ui_apps` 页面包**。当前两个待机动画属于过渡实现，外部动画播放器完成后也必须迁移到 NAND。

## 3. 动画资源标准

### 3.1 出厂数量

- 默认出厂动画目标：50 个。
- 出厂动画硬上限：60 个。
- 超出上限的动画必须作为可下载资源包，不得继续扩大基础固件包。
- 状态机只依赖稳定的动画 ID，不得依赖文件名或资源是否出厂内置。

### 3.2 正式编码规格

所有正式动画必须由同一套构建工具生成：

| 项目 | 约束 |
| --- | --- |
| 源素材 | 原项目 640 × 360、24 fps、带 Alpha 的 WebM |
| 输出画布 | 256 × 282 px |
| 播放帧率 | 保留源素材 24 fps |
| 抽帧 | 禁止 |
| 时长 | 保留完整源时长，禁止为了容量截断动作 |
| 编码 | 适合开发板硬件解码的 JPEG 帧动画 |
| JPEG 质量 | 68–72；默认 70 |
| Alpha | 不在设备端保留；构建时与产品背景合成 |
| 像素格式 | 与 RGB565 UI 管线兼容 |
| 循环 | 待机类无限循环；瞬时动作默认一次 |

如真机性能不足，优化顺序必须是：

1. 降低 JPEG 质量，但不得低于 65。
2. 将画布降至 240 × 270。
3. 优化预取、缓存和解码调度。

在没有新的产品决策前，**不得通过删除帧或截短动作来解决性能与容量问题**。

### 3.3 裁切与缩放

- 构建工具必须统计一个动作全部帧的 Alpha 联合边界。
- 联合边界四周应该至少保留 6 px 安全边距。
- 一个动作的全部帧必须使用相同的裁切、缩放和位移参数。
- 动作中的角色、头发、肢体和需要保留的特效不得被裁掉。
- 内容超出标准画布时，应等比缩小整个动作，不得逐帧缩放。
- 构建工具必须输出越界与缩放比例报告，异常动作需要人工复核。

### 3.4 播放与切换

- 动画必须从 NAND 按需读取，不能一次加载全部动画。
- 播放器应该使用当前动画和下一动画的双缓冲/预取策略。
- 瞬时动作必须收到真实播放完成事件后再切换状态。
- 禁止用硬编码秒数强制截断正式动作；清单中的时长只能作为超时保护。
- 同一个瞬时动画每次重新播放必须从第 1 帧开始。
- 待机呼吸持续循环；每次回到呼吸后重新抽取 60–120 秒的随机等待，再完整播放一次“东张西望”。
- 安全事件、关机和明确的用户取消可以中断动画；普通状态切换必须等待不可中断动作结束。

### 3.5 动画清单

每个资源包必须包含版本化清单，至少包含：

```json
{
  "schema_version": 1,
  "pack_id": "fatfish-core-v1",
  "animations": [
    {
      "id": "idle_breathing",
      "path": "animations/idle_breathing.pack",
      "width": 256,
      "height": 282,
      "fps": 24,
      "duration_ms": 10042,
      "loop_count": 0,
      "interruptible": true,
      "tags": ["idle", "calm"],
      "crc32": "00000000"
    }
  ]
}
```

文件扩展名可以由最终外部资源容器决定，但清单字段与动画 ID 必须保持稳定。资源校验失败时必须回退到内置静态图或基础动画。

## 4. NAND 容量预算

1 GiB NAND 不得全部分配给动画。目标预算如下：

| 用途 | 建议预算 |
| --- | ---: |
| 50 个完整 24 fps 动画 | 160–300 MiB |
| 音效与本地预设语音 | 50–100 MiB |
| Agent/聊天缓存与摘要 | 100–150 MiB |
| OTA、资源包下载和回滚暂存 | 150–200 MiB |
| 日志、用户数据与未来功能 | 100 MiB |
| 文件系统、磨损与安全余量 | 至少 150 MiB |

约束：

- 动画区默认配额 300 MiB，未经重新测算不得提高。
- 聊天缓存必须有大小与保留时间上限。
- 下载更新前必须同时校验资源包大小、暂存空间和回滚空间。
- 不得因为动画资源不足而占用 OTA 或文件系统安全余量。
- 原始 WebM、GIF 和设备格式动画不得在 NAND 中重复保存；设备只保存可播放格式。

## 5. ASR 与本地 Agent 边界

### 5.1 设备端职责

设备端负责：

- 按键或轻量 VAD 决定何时开始录音。
- 采集并流式发送音频。
- 显示监听、思考、回复、错误和离线状态。
- 接收 Agent 的结构化回复。
- 播放 TTS、提示音和动画。
- 执行权限检查、状态优先级和中断策略。
- 断线时提供基础触摸、按钮和预设互动。

设备端不负责：

- 开放式中文 ASR 模型推理。
- 本地大语言模型推理。
- 长期对话记忆整理。
- Agent 任意工具调用决策。

设备端可以在未来加入唤醒词或有限命令词识别，但不得把它设计成开放式 ASR 的替代品。

### 5.2 Agent 端职责

本地 Agent 服务负责：

- 流式 ASR 与 partial/final 文本。
- 角色提示词和系统提示词。
- 多轮对话、记忆摘要和上下文裁剪。
- 工具调用与权限策略。
- 文本回复和可选流式 TTS。
- 将自然语言结果映射为允许的情绪和动作 ID。
- 可选的云端模型或云端 ASR 回退。

Agent 服务可以完全在局域网运行。是否连接云端由用户配置决定，设备固件不得假设公网始终可用。

### 5.3 音频格式

设备到 Agent 的基础音频格式固定为：

- 采样率：16 kHz。
- 声道：单声道。
- 位深：16-bit signed PCM little-endian。
- 建议分片：20 ms，即每片 640 字节。

控制消息使用 JSON，连续音频使用 WebSocket 二进制帧。禁止将 PCM 字节 Base64 后塞入 JSON。

## 6. Fatfish Agent 协议

应该新增独立的 `local_agent`/`fatfish_agent` Provider，而不是让服务器永久模拟某个云厂商的专用协议。

建议连接方式：

```text
ws://<agent-host>:<port>/v1/device
wss://<agent-host>:<port>/v1/device
```

最低消息集合：

- `device.hello`：设备 ID、固件版本、协议版本和能力清单。
- `session.start` / `session.end`：会话生命周期。
- `audio.start` / binary audio / `audio.end`：音频流。
- `asr.partial` / `asr.final`：识别结果。
- `agent.delta` / `agent.final`：流式和最终回复。
- `interaction.command`：情绪、动作、提示音、TTS 与中断属性。
- `interaction.cancel`：取消当前回复。
- `playback.started` / `playback.finished` / `playback.error`：设备播放反馈。
- `error`：版本、鉴权、ASR、Agent 或播放错误。

`interaction.command` 示例：

```json
{
  "type": "interaction.command",
  "request_id": "req-123",
  "text": "我在听呀",
  "emotion": "curious",
  "action_id": "look_around",
  "speech": {
    "mode": "stream",
    "content_type": "audio/pcm"
  },
  "interruptible": true,
  "expires_ms": 15000
}
```

协议约束：

- Agent 只能发送清单中存在的 `action_id`，不得发送任意文件路径。
- 设备是硬件动作的最终仲裁者，有权拒绝过期、无权限或状态冲突的命令。
- 每个命令必须包含可追踪的请求 ID。
- 重连后不得盲目重放已过期动作。
- 协议必须协商版本；不兼容时进入明确的离线状态。

## 7. 统一互动调度器

动画、ASR、Agent、按钮、触摸和系统事件必须通过一个统一调度器进入状态机，不得分别直接控制 UI。

建议优先级从高到低：

1. 关机、低电量、硬件错误和安全事件。
2. 用户明确取消、按键和当前语音输入。
3. 正在播放的 Agent 回复或本地确认反馈。
4. 通知和传感器触发互动。
5. 待机随机动作。

至少支持这些顶层状态：

```text
BOOT
IDLE_BREATHING
IDLE_ACTION
LISTENING
THINKING
SPEAKING
OFFLINE
ERROR
SLEEP
```

状态转换必须记录原因和请求 ID，以便串口日志和问题复现。Agent 回复不能绕过状态机直接显隐动画对象。

## 8. 提示词与记忆

- 角色系统提示词由 Agent 服务器管理并版本化。
- 设备只保存必要配置、短期摘要和最近事件，不保存完整模型提示词副本作为业务真源。
- 本地离线互动使用版本化的规则包，内容包括触发条件、冷却时间、动作 ID、预设文本和音效 ID。
- 设备上传给 Agent 的上下文必须有大小上限；优先发送摘要、当前状态、最近事件和用户本轮输入。
- 原始音频默认不持久化。
- 聊天历史必须支持用户清除、自动过期与容量淘汰。

## 9. 隐私、安全与降级

- 默认不持续上传麦克风音频；按钮、VAD 或唤醒事件后才开始发送。
- UI 必须明确显示监听状态。
- 局域网连接也必须有设备身份与令牌认证。
- 跨越可信局域网时必须使用 WSS/TLS。
- 凭据不得写入动画包、日志或公开配置页面响应。
- Agent 工具必须使用能力白名单；远程文本不得直接变成文件路径、Shell 命令或硬件调用。
- Agent 不可用时，设备应回到呼吸待机并提示离线，不得卡在 THINKING。
- ASR 超时、TTS 中断和网络断开必须可取消并释放音频设备。

## 10. 实施顺序

后续实现应按以下顺序推进：

1. 将现有两个动画迁移到 NAND 外部资源包。
2. 建立动画清单、校验、按需加载和播放完成回调。
3. 完成统一互动事件与状态仲裁器。
4. 定义 Fatfish Agent WebSocket 协议和 Provider 接口。
5. 接入设备音频流与本地 Agent ASR。
6. 接入 Agent 文本、动作命令和取消机制。
7. 接入流式 TTS 与播放反馈。
8. 完成聊天摘要、缓存配额、隐私和清除功能。
9. 用 5 个代表动作做真机压力测试。
10. 批量转换并导入 50 个正式动画。

代表动作至少覆盖：呼吸、东张西望、快速转头、细微表情变化和最大范围位移/特效。

## 11. 验收门槛

批量导入动画前必须满足：

- 24 fps 动画连续播放无持续掉帧。
- 动画第二次播放从第 1 帧开始。
- 瞬时动作完整播放后才回待机。
- 播放动画时音频采集、网络和触摸仍可工作。
- Agent 断线不会导致 UI、音频或状态机死锁。
- NAND 资源损坏时可以安全回退。
- OTA 暂存和回滚空间不被动画占用。
- 连续运行测试中无明显内存增长。

## 12. 尚未锁定的选择

以下项目需要通过原型测试后决定，不应由后续实现者自行假定：

- 本地 Agent 使用的具体 ASR、LLM 与 TTS 模型。
- Agent 服务发现方式：固定地址、mDNS 或配对流程。
- TTS 下行使用 PCM、Opus 或其他编码。
- 外部动画资源容器的最终格式和扩展名。
- 最终 50 个出厂动作名单。
- 是否加入设备端唤醒词或有限命令词识别。

改变本文中的硬约束时，应同时更新容量测算、状态机协议和验收测试。
